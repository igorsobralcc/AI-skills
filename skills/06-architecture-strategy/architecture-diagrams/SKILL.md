# Architecture Diagrams

## Golden rules

- State the audience and question, then choose the smallest diagram type that answers it.
- Name systems, responsibilities, trust boundaries, protocols, data flows, and ownership consistently.
- Mark current and proposed states, include a legend and date, and keep source-controlled text diagrams when practical.
- Validate the diagram against specifications and implementation owners.

## Guardrails

- Do not create decorative exhaustive maps, expose secrets or unnecessary sensitive topology, or imply runtime behavior from static structure alone.
- Avoid mixed abstraction levels and unlabeled arrows.
- Update or supersede diagrams when architecture changes.
